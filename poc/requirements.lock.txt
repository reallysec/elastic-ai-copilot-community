# requirements.txt 说的是「我们要什么」，全是 >= 无上界 —— 同一个 git tag 今天和
# 三个月后 docker build 出来的依赖树不一样，而 license 模块是 Cython 编译进镜像的：
# 一次上游 breaking 会以「客户现场镜像起不来」的形式暴露，且复现不出来。
#
# 所以镜像装的是这份锁（见 Dockerfile），开发机仍然按 requirements.txt 装。
# 改了 requirements.txt 就要重生成这份，否则新依赖不会进镜像：
#
#   docker exec <gateway 容器> pip freeze | sort > poc/requirements.lock.txt
#
# backend/tests/test_requirements_lock.py 盯着「直接依赖都在锁里」。
